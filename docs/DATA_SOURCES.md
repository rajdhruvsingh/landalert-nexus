# Data Sources

This document explains where every data value in the risk engine comes from,
what real data would be needed to replace estimates, and how to obtain it.

---

## Slope data (`risk_zones.mean_slope_deg`)

### Current status

`mean_slope_deg` values are sourced from published district-level studies and
NDMA reports where available (see the `slope_source` column in `risk_zones`).
Zones marked `"Estimated"` in `slope_source` have no peer-reviewed backing and
must be replaced before operational deployment.

### How to compute from DEM (fuller fix — option b)

1. **Obtain DEM tiles** for NE India from one of:
   - **Bhuvan** (NRSC): https://bhuvan.nrsc.gov.in/  
     → Download CartoDEM v3R1 at 30m or 10m for the required districts.
   - **SRTM** (NASA): https://srtm.csi.cgiar.org/  
     → Download 3-arc-second (~90m) or 1-arc-second (~30m) tiles.
   - **ALOS PALSAR** (JAXA): https://www.eorc.jaxa.jp/ALOS/en/dataset/  
     → 12.5m resolution — best available free option for rugged terrain.

2. **Compute slope** for each zone centroid:

   Using `gdal` (command-line):
   ```bash
   gdaldem slope input_dem.tif slope.tif -p   # -p gives percent slope; remove for degrees
   # Then sample the slope raster at each zone centroid lat/lng:
   gdallocationinfo -wgs84 slope.tif <lng> <lat>
   ```

   Using a Node/TS script with `geotiff` + `@turf/turf`:
   ```ts
   import { fromFile } from 'geotiff';
   // Read the slope raster at each zone centroid coordinate.
   // See ml-notebooks/ for a Python notebook that does this with rasterio.
   ```

3. **Update the database**:
   ```sql
   UPDATE risk_zones
   SET mean_slope_deg = <computed_value>,
       slope_source = 'SRTM 30m DEM, computed with gdaldem slope, <date>'
   WHERE id = <zone_id>;
   ```

## Rainfall thresholds (`threshold_e_mm`, `threshold_i_coefficient`, `threshold_i_exponent`)

### Key papers

| Reference | What it provides |
|-----------|-----------------|
| Sengupta et al. (2010) | NE-Himalaya E-D threshold: E = -11.10 + 0.62*D (valid 24 < D < 1440 hr) |
| Das et al. (2018) NHESS 18:2759-2775 | Sikkim-specific I-D threshold: I = 43.26 * D^-0.78 |
| Mathew et al. (2014) Geomorphology 228:307-319 | Regional NE-Himalaya I-D baseline: I ≈ 36.0 * D^-0.72 |
| Dikshit & Satyam (2019) Geomatics Nat Hazards Risk 10(1) | Sikkim antecedent E threshold ~420-440 mm |
| Boro et al. (2021) Landslides 18(4) | Assam (Dima Hasao/Karbi) antecedent 380-400 mm |
| Pachuau & Lallianthanga (2017) IJDR 7(3) | Mizoram (Aizawl) antecedent ~410-450 mm |
| Saikia & Sarma (2019) Nat Hazards 97(1) | Arunachal Pradesh antecedent 390-420 mm |
| NDMA NER Atlas 2021 | District-level slope statistics, Table B-3 |

### Per-state calibration status

| State | threshold_e_mm | Status |
|-------|---------------|--------|
| Sikkim | 430 | Calibrated — Das et al. 2018 |
| Mizoram | 430 | State-level estimate — Pachuau 2017 |
| Meghalaya | 465 | State-level estimate — NDMA 2019 |
| Arunachal Pradesh | 405 | State-level estimate — Saikia 2019 |
| Assam | 390 | State-level estimate — Boro 2021 |
| Manipur | 400 | State-level estimate — NDMA 2021 |
| Nagaland | 410 | Regional average — no Nagaland-specific study found |
| Tripura | 400 | Regional average — no Tripura-specific study found |

To replace any estimate with a calibrated value: update `risk_zones` with a new
`threshold_e_mm` and set `threshold_source` to the paper/report citation.

## Historical landslide inventory (`historical_landslides`)

### Current status

All rows are **synthetic fixtures** generated by modulo arithmetic (see
`supabase/migrations/20260831092339_*.sql`).  The `is_synthetic = true` column
and source label make this explicit.  They must NOT be presented to judges as
real inventory data.

### How to obtain real data

| Source | Access | Format |
|--------|--------|--------|
| **GSI Bhukosh** | https://bhukosh.gsi.gov.in/ — free registration | Shapefile / CSV |
| **Mathew et al. 2014 catalogue** | Supplementary data in Geomorphology 228:307-319 (~490 NE Himalaya events) | CSV in paper SI |
| **NDMA Disaster database** | https://nidm.gov.in/disaster-database | CSV |

Once real data is obtained:
1. Add a migration that inserts the real events with `is_synthetic = false` and
   `source = 'GSI Bhukosh export YYYY-MM-DD'`.
2. Optionally DELETE the synthetic rows if you want a clean inventory, or retain
   them for UI completeness with the existing amber badge.
3. Retrain the model (see `docs/MODEL_EVALUATION.md` and `ml-notebooks/`).

## Soil moisture (`weather_readings.soil_moisture_pct`)

### Current status

Synthetic values generated by a cosine function on zone ID and day index
(see seed migration).  Range is approximately 38-83%.

### Real data source

**SMAP (NASA)** Level-3 soil moisture at 9km or 36km resolution:
- https://nsidc.org/data/spl3smp
- Free registration; daily global coverage.

**ESA CCI** combined active/passive soil moisture:
- https://www.esa-soilmoisture-cci.org/

Integration approach: download daily HDF5/NetCDF tiles, sample at each zone
centroid, INSERT into `weather_readings` via a scheduled edge function or
pg_cron job.
